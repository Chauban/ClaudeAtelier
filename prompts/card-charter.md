## 1. 轮换编号：K、L、S 三个强制值

K（冷知识领域 1~17）和 L（语言 1~7）由 UTC 小时数推算：

```
T=$(date -u +%s); N=$((T/3600)); K=$((N%17+1)) L=$((N%7+1))
```

> 这两个编号是强制的，不许自行更换。

风格 S：

> 取台账里最近 15 条用过的 S，从 1~47 里排除掉，在剩下的候选中用 Python random 随机抽一个。台账不足 15 条就排除全部已有的。
>
> —— 抽到的 S 是强制的。不管你觉得哪个风格更好看、更好写、更保险，都必须严格执行，绝对不许自行更换。这套机制唯一的目的就是防止风格反复重复（此前出现过连续多次只在孟菲斯和瑞士国际主义之间打转的问题）。抽到不熟悉的风格，也要认真做出该风格的典型特征，而不是退回到熟悉的风格。

〔改动 ⑤，新增〕**共享风格班**：

> 当 `N % 24 == 4`（即本地 12:00 那一班）时，S **不按上面的排除法抽取**，改为直接由 N 算出：〔**改动 ⑤**，整条新增，原文无此规定。〕
>
> ```
> S = (N / 24 * 17) % 47 + 1        整数除法   〔改动 ⑤〕
> ```
>
> —— 这一班的 S 同样是强制的，并且**优先于排除规则**：哪怕这个风格你最近刚做过，也照做。〔改动 ⑤〕

*（为什么这一班要例外：平时各方的领域和语言相同、风格各自随机，于是「模型」和「风格」两个变量混在一起，看不出差别来自哪一个。共享风格班把风格这个变量按住，那一班的唯一变量就只剩执笔者本身。每天一组，47 天走遍全部 47 种风格。*

*跳步取 17 而不是 1，是因为风格表按类聚在一起（38~47 全是立体类），顺着走会连着一周都是 3D，正好犯了排除机制要防的毛病。47 是质数，任何 1~46 的跳步都能不重不漏走遍全部 47 种。*

*这个值必须由各方**各自从 N 独立算出**，不是谁去读别人的台账看它抽了什么——后者在只有两方时勉强能用，方数一多就散架，也破坏了各自不读别人台账的隔离。同一个 N 算出同一个 S，无论有多少方参与都成立。）*

*（K、L、S 由谁计算因运行环境而异——有的自己跑 shell 算，有的由编排器算好递进来。规则一致，执行者不同。拿到值之后的义务完全相同：照做，不许换。）*

## 3. 核实冷知识 —— 不许跳过

> 选定冷知识后，用搜索工具核实关键事实：人名、年份、数字、地名、因果关系。〔本行有两处改写：原文的具体工具名与加载方式属运行环境，此处泛化为「搜索工具」；原文「搜 1~2 次」并入下一条的修订。〕
>
> - **可以多次搜索，每次取多条结果**；允许「搜 → 读 → 再搜」逐步追问，不必一次定生死。数字、年份、人名一类的断言应尽量找到两个以上彼此独立的来源交叉印证。〔**改动 ①**：原文为「搜 1~2 次」，2026-08-10 放宽。理由是核实一条冷知识本就要分头查人名、年份、数字与因果，一两次不够；换题重来又是一轮。〕
> - 核不实、找不到像样来源、或发现细节记错了 → 换一条同领域的冷知识重搜，不要硬着头皮上。
> - 数字类（速度、年份、数量）尤其要核，宁可写"约"也不要写错。
> - 核实通过后把最靠谱的一个来源链接记进台账 source 列，卡片上不用印链接。

## 7. 卡片内容

> 一句话或一小段：让人心灵一振、优美动人、引人深思、有趣搞笑、冷幽默或让人释然的都行，每次尽量换一种调性，可以是名言、原创句子、诗句、段子。
>
> 加上按 K 选出、且已核实过的那条冷知识。两者放在同一张卡片上，用 L 对应的语言书写。

## 8. 编号与日期标识 —— 必须出现在卡面上

> 每张卡上要有本次流水号（NO.0042 这种四位补零）和日期（YYYY-MM-DD 或该风格惯用的写法）。
> 呈现方式要融入当次风格的语汇，不要固定成一个角标模板。举例：
> - CRT 终端 → `LOG #0042` / `2026-08-02 15:00`
> - 老报纸头版 → 「第 0042 期」「丙午年七月初九」配报头栏线
> - 工程蓝图 → 图框右下角标题栏 `DWG NO. 0042` / `DATE 2026-08-02`
> - 旧车票票根 → 票号 No.0042、日期戳
> - 像素游戏 → `LV.0042` / 底部状态栏日期
> - 黑胶唱片封套 → 唱片编号 `CAT. 0042`
> - 植物图鉴 → 标本标签 `SPECIMEN 0042 / coll. 2026-08-02`
> - 邮票信封 → 邮戳里的日期 + 邮票面值位置放编号
>
> 要像这个风格里本来就该有的东西，而不是硬贴上去的水印。字号可以小，但必须清晰可读。

*（流水号的前缀因产出方而异，由各自的环境说明给定；「四位补零、必须上卡、必须融入风格语汇」的要求相同。）*

## 9. 设计执行

> 严格按抽到的 S 做，配色、字体、装饰、留白、排版结构都要贴合该风格的典型特征，不要套同一个模板只换颜色。举例：包豪斯用红黄蓝三原色加几何色块和粗黑线；工程蓝图用深蓝底白色细线加尺寸标注和网格；老报纸用衬线字体、分栏、报头和栏线；像素风用马赛克色块和点阵字加硬边阴影；水墨风大面积留白配墨色晕染和竖排；Art Deco 用金黑配色加对称扇形放射纹；构成主义用红黑斜切构图和粗体斜排字。
>
> 竖版即可（高大于宽），比例每次可不同，逻辑宽度 800~1200px 自选，不必固定尺寸。

## 10. 渲染硬指标

> - 画布按 deviceScaleFactor=2 放大（例如逻辑 1000×1780 → 实际 2000×3560）。
> - 正文字号（逻辑像素）不小于 28px，避免过细字重。中文务必用 Noto CJK 字体，不能出现方框。
> - 先按行测量文本宽度确保不溢出边界，排版算好总高度再定画布高度，绝不能让内容超出画布或互相重叠。

*（用什么库、字体文件在哪、草稿放哪，属于环境差异，见各自的环境说明。）*

## 11. 成品自检

> 检查溢出、重叠、方框字、字号过小、编号日期是否清晰；有问题改脚本重渲染，直到画面干净。

*（这几项检查由谁执行、怎么执行因环境而异：有的看渲染出的图自检，有的由绘图接口当场报错拦截。要达到的标准相同。）*

## 12. 文件命名

> {前缀}{四位补零}_{YYYY-MM-DD}_S{S}-{风格简名}_{语言代码}.png　〔原文此处写死为 `NO.`；因各产出方使用各自的编号系列，改为 `{前缀}`，由环境说明给定。其余部分未动。〕
> 例：NO.0020_2026-08-03_S24-工程蓝图_ZH.png
> 语言代码：ZH / ZH-TW / ZH-HK / YUE / EN / JA / FR / DE / ES / KO / IT
> 风格简名取 4~8 字，不含 Windows 非法字符（\ / : * ? " < > |）。
> 台账 filename 列存相对路径，格式 `{YYYY-MM}/文件名.png`。
